Autenticación

Si no hay keys, la API está abierta. En cuanto creas la primera, POST /api/v1/build exige X-API-Key o Authorization: Bearer ib_.... Las keys se guardan en data/apikeys.json (ignorado en git): en disco sólo queda su hash sha256 y el prefijo.

curl -X POST /api/keys -H "Content-Type: application/json" -d '{"name":"ci"}' curl -H "X-API-Key: ib_xxx" https://TU_DOMINIO/api/v1/build -d '{"url":"https://example.com","name":"MiApp"}'

Compilar
POST/api/buildestudio

Config completa: appName, url o htmlCode, packageName, outputs (apk, aab, xapk, apks, ipa, exe, msi, dmg, appimage), platform (android/ios/both), permissions, plugins, provider, template, streamUrl, firma y webhookUrl → 202 {id, branch, status}.

curl -X POST /api/build -H "Content-Type: application/json" \ -d '{"appName":"Mi Tienda","url":"https://mi-tienda.com","packageName":"com.miempresa.miapp","outputs":["apk","aab"],"permissions":{"gps":true,"cameraMic":true}}'
POST/api/v1/buildAPI key

Versión versionada y más estrecha: url, name, package, output, outputs, platform, template, permissions, plugins, webhookUrl. Exige key si existe al menos una → 202 {buildId, status, branch}.

curl -X POST /api/v1/build -H "X-API-Key: ib_xxx" -H "Content-Type: application/json" \ -d '{"url":"https://example.com","name":"MiApp","package":"com.example.app","output":"apk"}'
GET/api/build/:idpolling

Estado cada 3 s: status queued|building|success|failed, step, runUrl, apkUrl. Si ya no está en memoria, mira el historial con fromHistory: true.

curl /api/build/abc123 # → {"id":"abc123","status":"success","step":"Build completado","apkUrl":"/api/download/abc123"}
GET/api/v1/build/:idpolling

Mismo estado en forma versionada con apkUrl, aabUrl, ipaUrl, outputs (lo que pediste) y formats (lo que existe de verdad).

POST/api/projectZIP

Genera el proyecto nativo en ZIP sin compilar en GitHub. Sirve para CI local o revisar los ficheros que saldrían.

curl -X POST /api/project -H "Content-Type: application/json" \ -d '{"appName":"Test","url":"https://example.com","template":"radio"}' --output proyecto.zip
Descargas
GET/api/download/:id/:fmt9 formatos

Formatos: apk (también sin sufijo), aab, ipa, xapk, apks, exe, msi, dmg, appimage. Abre el ZIP que subió Actions y devuelve el binario suelto. Sin runId → 404 "Build aun en progreso".

curl -L -o app.apk /api/download/abc123 curl -L -o app.dmg /api/download/abc123/dmg curl -L -o app.exe /api/download/abc123/exe
GET/api/apk-info/:id GET/api/build/:id/logs

Ficha del artefacto (nombre, tamaño en MB, enlace por formato) cuando la build ya terminó, y el log del run truncado a 80.000 caracteres.

GET/api/qr/:id

PNG del enlace de descarga para pegarlo en tarjetas o packs. ?size=400 para agrandarlo.

Permisos y análisis
GET/api/permissions/specPOST/api/permissions/audit

El Permission Engine con 86 entradas: spec devuelve todo; audit devuelve una fila por permiso con status (ok/warn/fail), minSdk, implementación nativa y si el provider lo soporta, más readiness y canBuild.

curl -X POST /api/permissions/audit -H "Content-Type: application/json" \ -d '{"appName":"Mi Tienda","url":"https://mi-tienda.com","permissions":{"foreground":true,"cameraMic":true}}'
GET/api/analyze?url=POST/api/analyze/html

Auditoría de la web: score 0-100, security, errors, optimization, frameworks, detectedApis y autoFix.preview con el HTML corregido. POST /api/analyze/fix devuelve sólo el HTML arreglado.

curl "/api/analyze?url=https://example.com" curl -X POST /api/analyze/fix -H "Content-Type: application/json" -d '{"html":"..."}'
POST/api/manifest-diffrelease check

Compara lo que pediste con lo que se genera: missing, unexpected y filas MATCH/MISSING. Frena releases con permisos de más o de menos.

curl -X POST /api/manifest-diff -H "Content-Type: application/json" \ -d '{"appName":"MiApp","url":"https://example.com","permissions":{"cameraMic":true}}'
POST/api/listingPOST/api/security-audit

Ficha de Play Store (título, descripción, keywords, categoría con los límites de Play Console) y auditoría con score, issues y comprobaciones GDPR. GET /api/privacy-policy?appName=&package= devuelve una base de política.

APK: inspección y descompilación
POST/api/inspect≤30 MB

Ficha técnica (packageName, versión, tamaño, .dex, .so, iconos), permisos detectados, riskyPermissions, findings y security.score.

curl -X POST /api/inspect -H "Content-Type: application/json" -d '{"apkBase64":"UEs..."}'
POST/api/decompilelocal ≤100 MB

Descompilación local: devuelve meta, importConfig (reimportable en el Studio), sourceZipBase64 y manifestPreview. Acepta apkBase64 con o sin prefijo data:, o cuerpo application/octet-stream.

curl -X POST /api/decompile -H "Content-Type: application/json" \ -d '{"apkBase64":"data:application/vnd.android.package-archive;base64,UEs..."}'
POST/api/decompile/cloudjadx + apktool

jadx 1.5.1 + apktool 2.9.3 en GitHub Actions (mismo runner que compila), límite 60 MB. Devuelve {id, statusUrl, downloadUrl}; consulta el estado y baja el ZIP. La rama se borra a los 20 minutos.

curl -X POST /api/decompile/cloud -H "Content-Type: application/json" -d '{"apkBase64":"UEs..."}' curl "/api/decompile/cloud/{id}/status" curl -L -o decompiled.zip "/api/decompile/cloud/{id}/download"
Automatización
GET/api/keysPOST/api/keysDELETE/api/keys/:id

Máximo 10 keys activas. El listado trae keyMask, uso y última llamada; la key en claro sólo se devuelve al crearla. DELETE hace borrado lógico (revokedAt) y esa key deja de servir.

POST/api/git/connectPOST/api/git/webhook

Conecta usuario/repo#branch con token (guardado con hash): cada push dispara una build. GET /api/git/integrations lista y DELETE /api/git/:id borra.

curl -X POST /api/git/webhook -H "Content-Type: application/json" \ -d '{"repository":{"full_name":"usuario/mi-web"},"ref":"refs/heads/main"}'
POST/api/versions/publishGET/api/check-update

Registro de versiones con changelog (hasta 20 por appId) para tu propio updater, más POST /api/cicd que devuelve el workflow listo para tu repo.

POSTwebhookUrleventos

Tu webhookUrl recibe POST con JSON: build.completed, build.failed y build.error.

Utilidades
GET/api/healthGET/api/diagGET/api/docs

health → {ok, version, githubReady}. diag revisa token, repo, rama y workflow en GitHub y devuelve un hint por paso. docs → resumen JSON de toda la API.

GET/api/historyGET/api/statsGET/api/templates

Historial local (30 entradas en el listado, 50 máximo en disco), totales por estado y duración media, y el catálogo de 29 plantillas con su audit resumido. GET /api/templates/:id/native genera los ficheros nativos sin compilar.

Ejemplos
const base = location.origin; const key = 'ib_xxx'; const r = await fetch(base + '/api/v1/build', { method: 'POST', headers: { 'Content-Type': 'application/json', 'X-API-Key': key }, body: JSON.stringify({ url: 'https://example.com', name: 'MiApp', output: 'apk' }) }); const { buildId } = await r.json(); let s; do { await new Promise(r => setTimeout(r, 3000)); s = await (await fetch(base + '/api/v1/build/' + buildId)).json(); console.log(s.status, s.step); } while (s.status === 'queued' || s.status === 'building'); if (s.status === 'success') location.href = base + s.apkUrl;
import requests, time base = "https://TU_DOMINIO" key = "ib_xxx" r = requests.post(f"{base}/api/v1/build", headers={"X-API-Key": key}, json={"url": "https://example.com", "name": "MiApp", "output": "apk"}) bid = r.json()["buildId"] while True: s = requests.get(f"{base}/api/v1/build/{bid}", headers={"X-API-Key": key}).json() print(s["status"], s.get("step")) if s["status"] not in ("queued", "building"): break time.sleep(3) if s["status"] == "success": open("app.apk", "wb").write(requests.get(base + s["apkUrl"]).content)
